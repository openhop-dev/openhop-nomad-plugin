Connectivity

Bridge the openHop companion frame server to the Project NOMAD HTTP API.

01

Default: 127.0.0.1. Address of the Repeater Companion TCP frame server, not NOMAD. Loopback works when the plugin and Companion run in the same host/container network namespace. For a separate host, use its reachable address and secure the connection on a trusted network.

Default: 5050. TCP port of your dedicated Companion identity in Repeater. Match the port configured there; another identity may use a different port. This is not the NOMAD HTTP port. Existing explicitly configured ports are preserved.

Default: http://nomad_admin:8080. Base HTTP(S) address of Project NOMAD, not a direct Ollama endpoint. The Docker name works only when Repeater and NOMAD share a user-defined network; preserve that network in Compose across recreation. For remote or standalone installs use a reachable hostname/IP. Loopback means the plugin’s own network namespace. Use the final URL: redirects and base paths are not supported.

Default: qwen2.5:3b-instruct. Exact model identifier NOMAD should use, including its tag. Choose a model already available to NOMAD; changing this field does not download one. Smaller models generally answer faster on limited hardware.

Optional NOMAD collection identifier sent with chat requests, for retrieval from a collection configured in NOMAD. Leave blank to omit it and let NOMAD apply its default behavior. This does not create or download a collection.

Default: 120 seconds. Total deadline for each NOMAD HTTP request, including DNS, connection/TLS, response headers and answer body. Slow models may need longer. This does not include waiting for a bridge concurrency slot or transmitting radio replies. A timeout returns an unavailable reply; it does not guarantee NOMAD has stopped generating.

Bridge behavior

Control concurrency, duplicate suppression, and prompt formatting behavior.

02

On: each question is stateless. Off (default): keep private per-sender conversation memory in RAM, up to 10 question/answer pairs and 16 KiB, for 30 minutes after the last successful answer. At most 64 senders; oldest conversations are evicted. /new or /reset clears your memory. Restart clears all memory. No NOMAD server sessions are created.

Default: on. Wraps the incoming question in the radio prompt template to request concise plain-text answers. Off sends the question without that wrapper; payload limits still apply.

Default: 1. Caps all accepted requests, including active handlers, requests waiting for a slot, and replies still being sent. Must be at least max concurrent requests. New messages above this limit are silently dropped.

Default: 2. Maximum accepted requests from one allowed sender within the rate limit window. Must not exceed the global limit. Excess requests are silently dropped.

Default: 4. Maximum accepted requests across all senders within the rate limit window. Works together with the per-sender cap; excess requests are silently dropped.

Default: 60 seconds. Rolling window used by both request rate limits. A longer window reduces how often senders can submit requests. Must be greater than zero.

Leave this list empty to allow everyone. Add one or more public keys to enable the whitelist—only listed senders are allowed. Enter only the first 12 hexadecimal characters of each sender's public key, not the full key. One prefix per line or comma-separated; blank entries are ignored. Only senders who can DM this Companion can use the bridge; rate limits still apply.

Default: 1. Maximum simultaneous request handlers. A slot remains occupied while NOMAD answers and the radio reply is sent, not just during HTTP inference. Must not exceed max pending requests.

Default: 5 seconds. How long an accepted request waits for a concurrency slot before returning a busy reply. Zero returns busy immediately when all slots are occupied; this is not the NOMAD HTTP timeout.

Default: 600 seconds; minimum: 60. How long recently seen message identifiers are remembered to suppress retransmitted duplicates. This does not block every identical question indefinitely.

Default: INFO. Controls plugin log verbosity, from detailed DEBUG diagnostics to CRITICAL only. DEBUG can expose operational metadata; use it temporarily when troubleshooting.

Required. Must include {question} so the incoming user message can be injected.

Default: concise radio-answer instructions. Use {question} to insert the received question. Only that substitution is allowed; use double braces for literal braces. The template must remain valid even when the radio prompt is disabled.

Radio payload limits

Tune downstream chunking limits to match your mesh link quality and radio constraints.

03

Default: 2 seconds; range: 0–60. Global minimum spacing between outgoing sends, shared by concurrent answers and error replies. Zero disables pacing. Companion acceptance is not confirmation of RF delivery.

Default: 4. Maximum chunks in one answer. Longer answers are truncated to this budget. More chunks use more airtime; failed or unconfirmed Companion acceptance stops the remaining answer.

Default: 80 UTF-8 bytes per chunk; minimum: 40. Includes chunk numbering. Non-ASCII characters may use multiple bytes. Smaller chunks suit constrained links; a larger value does not increase the radio protocol capacity.

Default: 1000 UTF-8 bytes. Maximum incoming question size before the radio prompt template is added. Oversized questions receive a short error instead of being sent to NOMAD.

Companion device settings

Read or apply settings on the running Companion connection. This is separate from Save and restart; unsaved connection fields above are not used. Changes affect the Companion identity, including other apps using it.

All automatically adds all contact types. None disables automatic contact addition, not direct messages or bridge access. Existing Selected mode is kept until you explicitly choose All or None. None clears the selected type bits; All retains them for other apps. No existing contacts are deleted.

Allow the Companion to replace its oldest eligible contact when its contact table is full. This changes the overwrite flag only; other flags and any maximum-hop limit are preserved.

Companion path hash width: 1, 2 or 3 bytes per hop (protocol modes 0, 1 or 2). This is not message chunk size. Wider hashes reduce collisions but use more path space. Requires a Companion that reports and supports this mode.
